# Instalación del invitado de auditoría

La auditoría semanal no usa el socket Docker del bastión ni el de producción. El recolector de confianza permanece en el bastión; sólo él accede por SSH a producción para leer inventario y, si falta una imagen en caché, exportarla por ID. El invitado recibe la selección pública y archivos sellados en un disco ISO de solo lectura y devuelve el resultado por QEMU Guest Agent. No hay SSH, puertos redirigidos, agentes reenviados, volúmenes compartidos ni carpetas del bastión en el dominio. La salida a Internet usa la interfaz de usuario de QEMU para dependencias públicas, sin puentes ni cambios en una red libvirt compartida. Esto no equivale a un firewall de salida; el invitado no recibe credenciales para ningún servicio.

## Preparación autorizada, una sola vez

1. En el bastión Linux/amd64, use KVM/libvirt (`qemu:///system`), `qemu-img`, `xorriso`, Git y el Node 24 ya instalado. Reserve `/var/lib/libvirt/images/allnutrition-audit` como directorio nuevo, controlado por root y sin escritura para grupo/otros; QEMU debe poder atravesarlo (modo `0711`, o `0750` con el grupo real de QEMU). No reutilice discos, MVs, redes ni el UID 1000 del bastión.
2. Prepare **sólo un invitado nuevo** desde una distribución Linux amd64 autenticada (por ejemplo, Ubuntu 24.04 Noble, verificando firma de `SHA256SUMS` y SHA-256 de la imagen publicada). La imagen final debe arrancar desde un disco virtio con BIOS/q35, tener una raíz de al menos 100 GiB virtuales y ser qcow2 autónoma, sin backing ni archivos de datos externos. Configure DHCP con la interfaz de usuario de QEMU. No use imágenes de aplicaciones existentes.
3. Dentro de ese invitado instale y habilite `qemu-guest-agent` y Docker **local** con Compose v2 y Buildx (Docker Engine y plugins oficiales); instale Git, `util-linux`, OpenSSL, gzip, tar, FFmpeg y Node 24 con npm/npx (`node` accesible como `/usr/local/bin/node`). Instale dependencias Linux de Chromium con la versión Playwright del candidato (`npx playwright install-deps chromium` en preparación). Habilite Docker con `/run/docker.sock` local, sin TLS remoto, sin escuchas TCP ni volúmenes externos. En el invitado cree o renombre la cuenta de pruebas a `allnutrition-audit`, UID/GID 1000; no requiere login. El arnés le da únicamente el grupo `docker` del invitado al ejecutar. La coincidencia numérica hace que los bind mounts de medios, llaves sintéticas y PostgreSQL de la propia VM respeten `0700`/`0600`: no use rootless ni `userns-remap` en este daemon dedicado.
4. Instale `deploy/audit/guest.mjs` revisado como `/opt/allnutrition-audit/guest.mjs` **dentro del invitado**, propietario root y no modificable por la cuenta de pruebas en la imagen de referencia. Apague y selle la imagen sin identidades, claves de servidor SSH, archivos de credenciales, contenido productivo ni montajes host; no arranque `sshd` ni permita que cloud-init genere claves. En el bastión coloque sólo esa imagen de referencia en `/var/lib/libvirt/images/allnutrition-audit/golden.qcow2`, dueño root, `0444` (o `0440` con grupo QEMU); no debe abrirse para escritura. Conserve su hash de aprovisionamiento fuera del invitado. Cada ejecución usa un overlay nuevo y lo elimina; el invitado nunca reutiliza su propio estado modificable.
5. Instale una fuente revisada del recolector en `/opt/allnutrition-audit` **en el bastión**. Configure `/etc/allnutrition-audit/production.env` y la identidad de lectura de producción bajo `/etc/allnutrition-audit/`, archivos root `0600`, directorio root `0700`; no copie esos archivos dentro de la imagen de referencia. Los archivos de fuente sellados deben existir en la caché del operador. Instale las unidades `deploy/systemd/allnutrition-audit.{service,timer}` sin habilitar todavía el timer.

`provision-golden.sh` automatiza los pasos de referencia dentro de un único dominio transitorio. Desde un checkout de herramientas aprobado, páselo por el transporte del bastión con `sudo -n bash -s -- <base64-de-deploy/audit/guest.mjs>`; la carga Base64 contiene sólo ese arnés público. Requiere que el directorio de auditoría todavía no exista y aborta sin reemplazar discos. Comprueba el checksum firmado con la [clave publicada por Ubuntu](https://ubuntu.com/docs/public-images/public-images-how-to/verify-image-checksum/), Docker desde su repo APT firmado, y [Node 24 firmado](https://github.com/nodejs/node/blob/v24.22.2/README.md#verifying-binaries). No se instala nada en el bastión.

Para una instalación inicial repetible, empaquete sin modificar el checkout estos archivos públicos: `scripts/{audit-production,audit-issues,production-host,production-release,release-impact,release-impact-matrix}.mjs`, `deploy/audit/` y `deploy/systemd/allnutrition-audit.{service,timer}`. Pase ese tar por stdin a `install-builder.sh <destino-ssh-vm> <ruta-identidad-existente-en-bastión> <sha256-golden>` como root en el bastión. El instalador extrae sólo su lista de archivos públicos. La identidad se copia localmente, sólo a `vm-identity` dentro de `/etc/allnutrition-audit` (no debe incluirse en el tar). Requiere la host key previamente verificada en el `known_hosts` de root; no agrega ni reemplaza entradas. Instala las unidades sin activar ninguna.

## Aceptación antes de habilitar

Use primero una instantánea sintética sellada con los cinco IDs Linux/amd64 y sus hashes. Confirme arranque y `guest-ping`, acceso de QEMU a la imagen de referencia/overlay y acceso de la cuenta UID/GID 1000 a los binds privados exclusivamente dentro del invitado. El auditor debe rechazar una imagen adulterada, un SHA de fuente incorrecto o un informe con una compuerta faltante. Revise que no queden dominio ni directorio `run-*` tras éxito, error o stop. `ExecStopPost` sólo procesa el UUID y directorio registrados en `/var/lib/allnutrition-audit/active-guest.json`; si no puede confirmar que el dominio desapareció, conserva los archivos para recuperación.

Para un humo independiente sin producción, genere un UUID aleatorio y el XML con `auditGuestDomain(uuid, '/var/lib/libvirt/images/allnutrition-audit/smoke-' + uuid)` desde `deploy/audit/guest-host.mjs`. Envíe `smoke-golden.sh` al bastión con `sudo -n bash -s -- <uuid> <base64-del-xml>`. Sólo usa una imagen pública de Node y un archivo sintético; verifica ausencia de identidad SSH/host shares y paso del bind `0700`/`0600` al Docker exclusivo. No habilita el timer.

Para acreditar únicamente el par operativo antes de un corte, ejecute en el bastión `flock -w 120 /var/lib/allnutrition-audit/audit.lock /home/allnutrition/native-toolchain-91b7ab6b/bin/node /opt/allnutrition-audit/deploy/audit/guest-host.mjs --pair <manifest.json> [sha256-bundle]`. El manifiesto es el destino, no el estado vivo. El SHA opcional apunta a `cache/bundles/<sha256>.tar.gz`; sin él se usan los archivos exactos `cache/images/<id-sin-sha256>.tar.gz`. Una imagen heredada no cacheada se exporta de la VM por ID, sólo lectura. El proceso devuelve exclusivamente `{accepted, zeroOwnedLeftovers, images}` en stdout o sale no cero. El recolector conserva la clave; el invitado recibe sólo el ISO de entrada. El arnés actualizado `guest.mjs` viene de la instalación confiable del bastión, no del árbol del candidato.

Después de un corte verificado y de aceptar el entorno, `systemctl start --no-block allnutrition-audit.service`, inspeccione `/var/lib/allnutrition-audit/last.json` y habilite `systemctl enable --now allnutrition-audit.timer`. Compruebe el próximo domingo a las 08:17 UTC. Ninguna de estas operaciones instala software ni cambia configuración en la VM de producción.

## Registro público de hallazgos

El recolector registra fallos de auditoría y el recuento de trabajos recientes fallidos en [Issues](https://github.com/HenderOrlando/allnutrition/issues), aunque la suite aislada pase. Un informe limpio o superado no escribe en GitHub. El cuerpo público contiene solamente categoría, etapa permitida cuando corresponda, commit desplegado abreviado (o «no verificado»), recuento y una acción de revisión. Los errores, claves de trabajos, identificadores internos y datos de usuarios quedan en los informes privados del bastión.

Antes de esperar publicación automática, configure `ALLNUTRITION_AUDIT_GITHUB_ACTOR` en `/etc/allnutrition-audit/production.env` con el usuario responsable de los Issues. Mediante el mecanismo seguro de aprovisionamiento del operador, coloque un PAT **fine-grained** de esa misma cuenta en `/etc/allnutrition-audit/github-issues-token`, `root:root` `0600`, archivo regular sin symlinks. Alcance: sólo `HenderOrlando/allnutrition`, permiso Issues lectura/escritura y Metadata lectura obligatorio. No use un token clásico ni copie las credenciales de `gh`. El recolector abre ese archivo únicamente si hay hallazgos; no lo pasa por argumentos, variables, SSH, ISO ni al invitado. No ponga el token en el tar ni en el archivo de entorno.

El recolector verifica identidad y autor antes de reutilizar un Issue por su marcador estable. Una recurrencia más reciente actualiza o reabre ese mismo Issue; una observación vieja no reemplaza un Issue actualizado después. No se cierran Issues automáticamente ni se escriben comentarios. Un marcador ambiguo o ajeno se rechaza sin modificar el Issue.

`last.json`, los informes históricos y `npm run deploy:production -- --status` separan el resultado de la suite de `publication`. La falta de credencial se registra como `publication.status=failed`, `code=invalid-credential` y la unidad falla si debía publicar; no impide correr la auditoría ni afecta a un informe limpio. Tras corregir la causa, reintente **sólo** el último informe pendiente bajo el mismo lock, sin arrancar el invitado ni tomar una nueva medición:

```sh
sudo -n bash -c 'set -a; . /etc/allnutrition-audit/production.env; set +a; exec flock -n /var/lib/allnutrition-audit/audit.lock /home/allnutrition/native-toolchain-91b7ab6b/bin/node /opt/allnutrition-audit/scripts/audit-production.mjs --publish-pending'
```

El reintento comprueba que el conjunto observado sigue activo cuando hay un inventario verificado. Si GitHub no confirma una creación, el intento privado evita duplicados: el reintento busca el marcador de nuevo, pero no repite un POST incierto. Para `create-unconfirmed`, el operador debe reconciliar el Issue con la cuenta configurada en GitHub antes de retirar el intento correspondiente de `/var/lib/allnutrition-audit/issue-create-intents.json`, bajo `audit.lock`. No reenvíe registros antiguos desde el historial.
